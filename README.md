# ShipProof

ShipProof combines public GitHub repository facts with a developer-written project story. Commit history is repository activity; it does not prove a feature works or establish an individual's contribution.

## Requirements

- PHP 8.2 or newer with Laravel's required extensions
- Composer 2
- Node.js 20.19+ or 22.12+ and npm

The app uses Laravel 12, Inertia 3, React 19 with JavaScript/JSX, Vite 7, and Tailwind CSS 4. Public repository lookup does not require a GitHub token.

## Environment configuration

Start from `.env.example`; keep `.env` local and never commit it. The local setup uses SQLite, database-backed sessions and cache, and a database queue. `php artisan migrate` creates the required local tables. No GitHub credential is needed or used.

| Variable | Local value / purpose |
| --- | --- |
| `APP_KEY` | Generated by `php artisan key:generate`; do not share or commit it. |
| `APP_ENV` / `APP_DEBUG` | `local` / `true` for development; use `production` / `false` when deployed. |
| `APP_URL` | Local app URL, usually `http://127.0.0.1:8000`; set to the HTTPS service URL after deployment. |
| `DB_CONNECTION` / `DB_DATABASE` | SQLite and `database/database.sqlite` by default. |
| `SESSION_DRIVER` / `CACHE_STORE` / `QUEUE_CONNECTION` | `database` for local use; deployment can use `file`, `file`, and `sync` because ShipProof has no durable user data or queued work. |
| `ASSET_URL` | Leave unset locally; set to the HTTPS service URL on Render so compiled assets use HTTPS. |

## Run locally

From the project directory:

```powershell
composer install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
php artisan key:generate
if (!(Test-Path database/database.sqlite)) { New-Item -ItemType File database/database.sqlite | Out-Null }
php artisan migrate
npm ci
```

Open two terminals in the project directory and run:

```powershell
npm run dev
```

```powershell
php artisan serve
```

Open the URL printed by `php artisan serve`, usually http://127.0.0.1:8000.

## Try the case study flow

1. Enter a public repository URL such as `https://github.com/laravel/laravel`.
2. Write a summary and project story in your own words. The title starts with the repository name.
3. Choose **Preview case study** to review the editorial preview. **Back to editing** retains the current page's draft.
4. Choose **Export Markdown** to download the current case study as a `.md` file.

Story input is held in page memory only. Refreshing clears the draft and current repository lookup. The preview is local to the browser; there is no saved or permanent public showcase URL. GitHub API responses are tested with mocks, so automated tests do not require live GitHub access.

## $0 hobby deployment on Render

The repository includes a Docker setup for a single Render Web Service. In the Render dashboard, connect a repository you control, select **Docker**, point it at the root `Dockerfile`, and choose the **Free** instance. Set the following service environment variables; use the exact HTTPS URL Render assigns to the service for both URL values:

| Variable | Value |
| --- | --- |
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_KEY` | A unique value generated with `php artisan key:generate --show`; save it as a Render secret. |
| `APP_URL` | `https://<your-service>.onrender.com` |
| `ASSET_URL` | `https://<your-service>.onrender.com` |
| `DB_CONNECTION` | `sqlite` |
| `DB_DATABASE` | `/tmp/shipproof.sqlite` |
| `SESSION_DRIVER` | `file` |
| `CACHE_STORE` | `file` |
| `QUEUE_CONNECTION` | `sync` |
| `LOG_CHANNEL` | `stderr` |

Set `/up` as the health check path. The container builds the React assets, installs production Composer dependencies, creates the temporary SQLite schema on startup, and listens on Render's assigned port. No GitHub token, external database, or paid API is required. For a Docker image build outside Render, run `docker build -t shipproof .`; to run it locally, pass the variables above with a generated `APP_KEY` and publish port `10000`.

Render's Free web service is suitable for a hobby preview, not dependable production hosting: it has 0.1 CPU / 512 MB RAM, spins down after 15 minutes without traffic, can take about a minute to wake, and its filesystem is lost on restart, spin-down, or deploy. ShipProof stores no permanent user content, but active page sessions and the temporary SQLite file can be lost. The workspace receives 750 free instance hours per calendar month; free usage is suspended when those hours run out if no paid plan is used. Render can bill overages when a payment method is on file, so keep billing disabled if a hard $0 cap is required. Review Render's current [free service limits](https://render.com/docs/free) before connecting a repository.

Deployment steps: commit and push this project to a Git repository you control, create the Render Docker Web Service from that repository, configure the environment variables above, select Free, deploy, then verify `/up` and a public repository lookup. This repository currently has no commits or Git remotes configured; no remote or public service has been created by this QA task.
